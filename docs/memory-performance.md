# 主页面内存和绘制审查

本轮以主页面进程 RAM 低于 100 MB（100,000,000 bytes）为目标。**该整机目标尚未被本轮源码的发布版实测证明**：本轮遵循不构建应用的约束，验证了源码资源预算和回归；现有安装版与旧构建产物并不包含这些优化。

## 已完成的资源边界

| 资源 | 修改后的边界或行为 |
| --- | --- |
| 壁纸解码 | RGBA 像素最多 2,097,152，8 MiB；附近尺寸共用 64px 档位，保持源图比例 |
| 壁纸预模糊 | 同一时刻只有一个栅格化任务，待处理只保留最新请求；高斯外扩工作画布不超过 2 MiB |
| 壁纸像素常驻 | 原图与衍生模糊图合计上限 10 MiB；重建和换图时仍有短暂交接峰值 |
| Flutter 图片 LRU | 12 MiB、最多 64 项；活图片和引擎渲染纹理不计入这个 LRU 上限 |
| 标签页面 | 首屏仅构建当前页；按需构建，保留最近两页；关闭预加载时仅保留当前页 |
| 隐藏页面 | 禁用 ticker 和焦点；桌面页保留最后约束，避免缩放时给隐藏页整页重新布局 |
| 内存压力 | 清除可回收壁纸衍生图和非当前页面；不丢当前页草稿，不取消处理队列 |
| 导入字体 | 只注册用户选中的字体；不再启动时遍历注册全部字体；字体字节不留在服务缓存中 |
| 空闲后台 | 后端无请求时轮询逐步退避；队列硬件监控仅在可见且应用前台时采样和刷新 |
| 缩略图 | 限制进程并发与等待队列；在退出、管道排空和临时文件清理后释放名额 |
| 交互绘制 | 按压 feature 复用局部 Path / Paint / Shader，随 feature 释放；导航拖动仅更新位置与裁切，复用静态标签 |

4K、DPR 3 的预算计算中，壁纸解码边界为 1920×1024，约 7.5 MiB；模糊输出 871×490，约 1.63 MiB，高斯外扩工作面小于 2 MiB。代价是装饰壁纸保留约 1080p 细节，磨砂图使用更低分辨率。视频/图片处理文件和导出结果的分辨率不受这项 UI 预算影响。

这些是像素存储和对象保留边界，不能与 RSS 直接画等号。图像解码器临时内存、Flutter/Dart/GTK 动态库、字体、渲染器纹理池、交换链和驱动仍属于进程或 GPU 成本；LRU 清空也不代表操作系统会即时降低 RSS。

## 测量事实与限制

- 现有用户安装版进程曾显示 RSS 约 29 MiB，但另有约 85 MiB 换出，RSS 历史峰值约 250 MiB，不能用这个换出后的低值判断目标达成。
- 在独立 PID/网络命名空间、一次性 XDG 配置、私有 D-Bus / 空 keyring、Xvfb 软件 GL 中，现有安装版进程的启动观察值如下。这是**旧安装版的启动基线**，不是本轮优化后的主页面基准，也不代表硬件 GPU 上的稳态数值。

| 隔离显示尺寸 | 观察到的 RSS 范围 | 最后一次采样的 Swap |
| --- | ---: | ---: |
| 1280×800 | 324.7–466.9 MiB | 0 |
| 3840×2160 | 730.5–1153.4 MiB | 0 |

高分辨率交换链本身也需要预算：3840×2160 RGBA 的单个完整缓冲区约 31.6 MiB。缓冲数量、GPU/软件后端以及映射到 RSS 的方式取决于平台。因此本轮没有把固定图片上限误报成全进程小于 100 MB。

## 复测方法

下一次正常产生发布版后，在目标设备上打开主页面，保持可见，分别记录无文件、实际文件列表、默认玻璃、4K/高 DPR、页面来回切换后的稳态值。先等待初始化完成和短动画停止，再测 RSS、PSS、Swap 及高水位；请不要使用 debug / flutter_tester 的进程占用作为发布版结论。

Linux 可用只读脚本：

```sh
python3 tools/process_memory.py <PID>
```

脚本只读取指定进程的 procfs，不启动/关闭程序，不清缓存，不读取设置或密钥。Swap 非零时，应把换出状态一同报告；PSS 适合解释共享库，但目标仍按约定的 RSS 判断。macOS/Windows 应使用对应系统的进程内存工具，并保持相同窗口尺寸和测试场景。
