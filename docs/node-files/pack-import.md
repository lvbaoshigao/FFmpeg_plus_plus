# 5.5 封装、导入与调试

现在把写好的图真正交给软件。这里使用教程提供的工具，不需要安装第三方 Python 包。

## 1. 把工具和 JSON 放在一起

保存这两个文件到同一目录：

- [fppx_tool.py](/examples/fppx_tool.py)
- [clip-video.json](/examples/clip-video.json)

链接若在浏览器里显示文本，用“另存为”保留原文件名；注意别变成 `fppx_tool.py.txt`。打开终端，切换到这个目录。

以下命令用 `python3`。Windows 也可以把它替换成已安装 Python 的 `py -3` 或 `python`。

## 2. 先检查，再打包

```sh
python3 fppx_tool.py check clip-video.json
python3 fppx_tool.py pack clip-video.json clip-video.fppx --description "截取视频第2至8秒"
```

第一条检查基本结构、ID、连线、环路以及教程覆盖的部分参数。第二条写出**旧版 1.2 节点配置**。

工具不会覆盖已有目标。再次打包时，换个输出名，例如 `clip-video-v2.fppx`；文件名中的 v2 只是你自己的修订号，**不代表新版 FPPX 格式**。

::: info 工具能保证到哪一步？
它不是官方完整校验器。通过检查，不代表编码器存在、素材时长合适或所有参数组合有效。它有 16 MiB 解压 JSON、256 MiB 输入文件的工具自身限制，也不读取或执行媒体。
:::

## 3. 在软件里导入

推荐先走配置库，避免覆盖正在编辑的画布：

1. 打开“配置库”，使用节点配置的导入入口。
2. 选刚生成的 `.fppx`，确认它被识别为节点配置。
3. 编辑导入的配置，检查节点数、连线、参数和输出规则。
4. 普通视频示例应有 3 个节点、2 条数据线；控制示例则有 4 个节点、3 条连线和 1 个分组块。
5. 保存后，到项目页给一份至少 10 秒的视频副本应用该配置，再手动入队。

在节点编辑器内部也可以导入，但它会替换当前画布。先保存原有工作，再做这一步。

音频波形示例应应用到音频文件；别拿视频截取示例去套图片。输入媒体来自项目文件，配置不会自动给你创建媒体素材。

## 4. 必要时解包回来看看

```sh
python3 fppx_tool.py unpack clip-video.fppx recovered.json
python3 fppx_tool.py check recovered.json
```

它会恢复图 JSON 并打印描述。此工具只解包旧版 **1.2**，不承诺读取所有历史变体；新版或加密文件会明确拒绝。需要处理新版时，使用应用导入，再按支持条件重新导出旧版；含未知类型时也可能不能转成旧版。

## 常见错误对照

| 现象 | 先查什么 |
| --- | --- |
| 魔数不匹配 | 是不是把 JSON 直接改了后缀，或下载成 HTML 页面？ |
| JSON 解析失败 | 尾逗号、注释、单双引号、编码是否正确？ |
| 连线端点不存在 | `from` / `to` 与节点 `id` 是否逐字一致？ |
| 图里有节点，保存却报悬空 | 节点位置不代表连接关系，查看 connections |
| 通用节点提示选媒体类型 | 填 `params.media_type`，并匹配实际媒体 |
| 时间预览或类型转换报错 | 时间用数字，按示例保留小数点，不要写字符串 |
| 提示文件已存在 | 换目标名；工具故意不静默覆盖 |
| 导入成功，运行仍失败 | 看图校验、实际素材、FFmpeg 能力和任务日志 |

## 这一章的示例核验口径

随文三个示例提供 JSON 和对应旧版 .fppx，已通过结构检查、旧版打包/解包往返、应用当前图校验器检查，以及工作区现有 Linux 原生后端的导入和新版再导出/导入。核对了节点参数、连线与逻辑块；这不等于在全部平台做了媒体执行验收。你自己的素材仍需按上面的步骤小规模试跑。
