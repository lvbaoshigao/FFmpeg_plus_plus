# 5.5 封装、导入与调试

本页说明如何将已编写的图导入应用。所用工具无需安装第三方 Python 包。

## 1. 准备工具与 JSON 文件

保存这两个文件到同一目录：

- [fppx_tool.py](/examples/fppx_tool.py)
- [clip-video.json](/examples/clip-video.json)

如果浏览器将链接显示为文本，请使用“另存为”并保留原文件名，避免保存为 `fppx_tool.py.txt`。然后打开终端并切换到该目录。

以下命令使用 `python3`。在 Windows 上，可将其替换为已安装的 Python 命令 `py -3` 或 `python`。

## 2. 检查并打包

```sh
python3 fppx_tool.py check clip-video.json
python3 fppx_tool.py pack clip-video.json clip-video.fppx --description "截取视频第2至8秒"
```

第一条命令检查基本结构、ID、连线、环路和部分参数。第二条命令生成**旧版 1.2 节点配置**。

工具不会覆盖已存在的目标文件。再次打包时，请更换输出文件名，例如 `clip-video-v2.fppx`；文件名中的 v2 仅表示自定义修订号，**不代表新版 FPPX 格式**。

::: info 工具的校验范围
该工具不是完整的官方校验器。检查通过不代表相应编码器存在、素材时长合适或所有参数组合均有效。工具自身限制为解压后的 JSON 最大 16 MiB、输入文件最大 256 MiB；工具不会读取或执行媒体。
:::

## 3. 在应用中导入

建议优先通过配置库导入，以避免覆盖正在编辑的画布：

1. 打开“配置库”，使用节点配置的导入入口。
2. 选择刚生成的 `.fppx`，并确认其被识别为节点配置。
3. 编辑导入的配置，检查节点数、连线、参数和输出规则。
4. 普通视频示例应有 3 个节点、2 条数据线；控制示例则有 4 个节点、3 条连线和 1 个分组块。
5. 保存后，在项目页将该配置应用于一份至少 10 秒的视频副本，然后手动将任务加入队列。

也可直接在节点编辑器中导入，但该操作会替换当前画布。执行前应保存现有工作。

音频波形示例应应用于音频文件。视频截取示例不适用于图片。输入媒体来自项目文件，配置不会自动创建媒体素材。

## 4. 解包并检查

```sh
python3 fppx_tool.py unpack clip-video.fppx recovered.json
python3 fppx_tool.py check recovered.json
```

该命令会还原图 JSON 并打印描述。工具仅解包旧版 **1.2**，不保证读取所有历史变体；遇到新版或加密文件时会明确拒绝。处理新版文件时，应通过应用导入，并在支持的条件下重新导出旧版；包含未知类型的文件也可能无法转换为旧版。

## 常见错误对照

| 现象 | 先查什么 |
| --- | --- |
| 魔数不匹配 | 检查是否仅将 JSON 改为 .fppx 后缀，或是否下载到了 HTML 页面 |
| JSON 解析失败 | 检查尾逗号、注释、引号形式及编码 |
| 连线端点不存在 | 检查 `from` / `to` 与节点 `id` 是否逐字一致 |
| 保存时报告节点悬空 | 节点位置不表示连接关系；检查 connections |
| 通用节点提示选媒体类型 | 填 `params.media_type`，并匹配实际媒体 |
| 时间预览或类型转换报错 | 时间应使用数字，并按示例保留小数点；不要使用字符串 |
| 提示文件已存在 | 更换目标文件名；工具不会静默覆盖文件 |
| 导入成功但运行失败 | 检查图校验结果、实际素材、FFmpeg 能力和任务日志 |

## 示例验证范围

三个随附示例均提供 JSON 及对应的旧版 .fppx，并已通过结构检查、旧版打包/解包往返、应用当前图校验器检查，以及工作区现有 Linux 原生后端的导入和新版再导出/导入。验证内容包括节点参数、连线和逻辑块；这些检查不等同于在所有平台完成媒体执行验收。使用自有素材时，仍应按上述步骤进行小规模测试。
