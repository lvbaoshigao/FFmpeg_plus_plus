# 插件安全、兼容性与升级

WASM 模块只通过宿主的两个 JSON 导入交互，不能直接调用 Flutter、原生系统或 FFmpeg 进程。所有边界都应以宿主实际校验为准；“使用 WASM”本身不等于插件已经可信。

## 资源预算与异常隔离

| 项目 | 默认值 | 宿主硬上限 |
| --- | --- | --- |
| 线性内存 | 16 MiB | 64 MiB |
| 执行/续调时间 | 1000 ms | 5000 ms |
| 指令预算 fuel | 1,000,000 | 10,000,000 |
| 单次请求/响应 | — | 各 256 KiB |
| 一轮宿主 I/O 请求数 | — | 16（请求 ID 不可重复） |
| ZIP 压缩包 | — | 16 MiB |
| ZIP 展开总量 | — | 32 MiB |
| 单文件及 WASM 模块 | — | 8 MiB |
| manifest JSON | — | 256 KiB |
| ZIP 条目数 | — | 256 |
| 单次宿主 I/O 内容（Base64 编码前） | — | 128 KiB |
| 一轮宿主 I/O 内容总量 | — | 2 MiB |
| 单插件私有 data 用量 | — | 16 MiB、256 个文件 |

所有 WASM 实例重建、业务续调和宿主 I/O 共用清单 time_ms 指定的整轮墙钟时间，不会因 restart 或等待网络而重置。权限或路径错误返回 host_response.ok=false；超时、预算耗尽或取消会直接终止整轮调用，不继续执行 guest。

包内路径仅允许可移植 ASCII 相对路径（最长 240 字符），拒绝反斜杠、绝对路径、空段、. 和 .. 段、drive/UNC、Windows 设备别名、大小写折叠后重复条目，以及符号链接或特殊文件。禁止依赖平台路径规范化来“修正”不可信路径。

函数/表和响应结构也有限额。v1 不开放 WASI、线程、SIMD、Core start 或自动初始化导出。运行时在后端辅助工作线程运行；陷阱、超时、预算耗尽、非法内存范围和无效 JSON 作为插件错误返回。不要把同一进程内的 WASM 运行时描述为独立操作系统进程级防护。部署仍应及时更新可信运行时，并只启用可信来源的插件。

插件代码应在可用时间内返回可验证结果。编译器生成的模块必须有有界最大内存，不要导入 malloc、printf、系统 socket 或文件 API。无限循环和递归不是合法的等待方法；异步 I/O 用 continuation 协议。

## 文件权限

~~~json
{"permissions":{"files":{"read":true,"write":false},"network":[]}}
~~~

声明与授权是两件事：清单声明不自动授予能力。用户启用时选择同意的权限，宿主在每次调用时重新校验。file.read 与 file.write 分开授权，只能操作插件私有 data 子目录内的合法相对路径。拒绝目录穿越、绝对路径和符号链接逃逸；媒体源/输出文件路径由现有任务系统控制，不提供给 guest 作为任意文件访问能力。

## 网络权限

~~~json
{"permissions":{"files":{"read":false,"write":false},"network":["https://api.example.org"]}}
~~~

网络按精确 HTTPS origin 声明和授权，协议、主机、端口共同构成范围；不能用通配符或一个域名的授权访问另一个域名。请求只能走有界的 http.get 宿主 API，并受到响应大小、超时及目标校验约束。宿主不跟随重定向，也不发送浏览器 Cookie、应用 AI Key 等环境凭据；不能利用一次授权跳转到其他 origin。不要把 API 密钥写入包或 URL。

## 生命周期

- **安装**：先校验 ZIP 与清单；安装后保持禁用。只导入包不会自动应用主题或 AI 配置。
- **启用**：校验插件 API、应用版本范围和依赖。WASM Basic_info/Node_info 必须与清单语义一致。IsPreview=true 还需确认稳定性提示。
- **禁用**：停止后续插件调用并更新可用节点目录。已有节点和参数继续保留；依赖此插件的启用项也必须保持依赖安全。
- **卸载**：由管理页确认，移除插件安装；图中引用保留为不可执行的缺失插件节点，避免破坏用户文件。
- **关闭实验开关**：隐藏入口并停止插件执行，重新打开后仍受既有启用、兼容与权限检查约束。

## 版本与依赖

format_version 描述包格式，api_version 描述宿主 ABI，Basic_info.Version 描述插件自身版本，app_version 描述应用兼容范围；四者不能互相替代。版本范围以空格连接比较器，例如 >=1.0.0 <2.0.0。使用语义版本，明确处理预发布版本，不要按普通字符串排序。

~~~json
{
  "api_version": 1,
  "app_version": ">=6.0.0-beta2 <7.0.0",
  "dependencies": [{"id":"org.example.base","version":">=1.0.0 <2.0.0"}]
}
~~~

依赖的包必须已经安装、启用且版本满足约束。缺失、禁用、不兼容、自依赖或循环依赖均不能启用；不会在后台下载、安装或授权依赖。先处理依赖再启用使用方。

## 升级、回滚与持久化

使用相同插件 ID 的较新版本进行升级，先检验兼容性和包内容，再切换安装。升级不会自动启用或继承新的权限同意；预览版和权限提示需要重新审查。保留的上一版本可通过回滚恢复，之后仍须按当前环境检查并启用。

节点 ID 与 schema_version 是图文件的长期契约。v1 不提供任意 guest 数据迁移脚本；不要在原 schema_version 下破坏性改变参数含义。运行时只接受当前真实声明允许的参数；遇到不兼容的历史参数应显式拒绝执行并引导用户处理，不要静默重解释。

示例测试同时覆盖原始 WASM 与安装/启用路径。发布前请真实编译、导入、运行，并检查禁用/缺失插件、参数越界、预算耗尽和权限拒绝等失败路径。
