# 3.8 日志查看与故障定位

排查失败任务时，应保留输入条件、任务错误、实际命令与相关日志。应用提供全局日志页，以及各任务独立的命令与日志详情。

## 打开和筛选

桌面可用侧栏“日志”（若显示），也可从设置 → 高级 → 调试 → 查看日志进入。移动端入口是设置 → 工具 → 日志。

日志页提供全部、信息、FFmpeg、进度、错误、探针等筛选。可先通过“错误”定位异常时间，再切换至“全部”查看前后上下文，避免仅依据最后一条日志判断原因。

## 收集诊断报告

1. 复现一次问题，记下操作及媒体类型。
2. 在队列中展开失败任务，复制错误、实际命令与任务日志。
3. 在全局日志页选择相关条目，点击“复制选中”；或先筛选，再使用“复制全部”。
4. 补充软件版本、操作系统、FFmpeg 来源与是否启用硬件编码。
5. 分享前检查路径、用户名、接口地址与 MCP 令牌等信息，并按需脱敏。

> **“复制全部”复制当前筛选结果；“清空”清除全部全局日志。** 清空操作不受当前筛选类别限制，执行前须保存所需诊断信息。

## 日常日志与调试日志

| 选项 | 用途与限制 |
| --- | --- |
| 普通日志 | 日常查看导入、处理与错误 |
| 调试模式 | 按需要开启应用调试显示/行为，不等于永久保存日志 |
| 非常详细的日志 | 短期观察底层操作，记录更多，也可能增加开销 |
| 保存日志 | 需要写目录留存时开启，并检查路径可写 |
| 探针筛选 | 查看底层跟踪；未开详细跟踪时可能没有条目 |

内存日志仅保留最近 2000 条，磁盘日志也受大小限制，不能作为永久审计存档。复现问题后，应及时保存所需日志片段。

## 日志解释与排查范围

- FFmpeg 会向 stderr 写入诊断信息，红色显示不表示任务一定失败；应同时核对退出码与任务状态。
- 导入解析与媒体处理属于不同阶段：解析失败时检查文件可读性与 FFprobe；处理失败时检查命令、参数与编码器。
- 详细日志用于记录和分析问题，不会修复权限、网络或编码器故障。

其他排查方法见[常见问题](../reference/faq.md)，日志保存路径设置见[高级设置](../settings/advanced.md)。
