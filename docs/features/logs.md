# 3.8 日志：把问题缩小到一条证据

遇到失败时，最有用的不是只截一张“失败”卡片，而是保留输入条件、任务错误、实际命令和相关日志。应用有全局日志页，也有每个任务自己的命令/日志详情。

## 打开和筛选

桌面可用侧栏“日志”（若显示），也可从设置 → 高级 → 调试 → 查看日志进入。移动端入口是设置 → 工具 → 日志。

日志页有全部、信息、FFmpeg、进度、错误、探针等筛选。先点“错误”找时间点，再切“全部”补上下文，比只看最后一句更容易定位。

## 复制一段可用报告

1. 复现一次问题，记下操作及媒体类型。
2. 到队列展开失败任务，复制错误、实际命令及任务日志。
3. 到全局日志页选择相关条目，点“复制选中”；或先筛选，再“复制全部”。
4. 补软件版本、系统、FFmpeg 来源、是否硬编。
5. 分享前检查路径、用户名、接口地址、MCP 令牌等信息，按需遮盖。

> **“复制全部”复制当前筛选结果；“清空”清除全局日志。** 清空不是只删屏幕上这一类，先保存证据再清空。

## 日常日志与调试日志

| 选项 | 适合什么时候 |
| --- | --- |
| 普通日志 | 日常查看导入、处理与错误 |
| 调试模式 | 按需要开启应用调试显示/行为，不等于永久保存日志 |
| 非常详细的日志 | 短期观察底层操作，记录更多，也可能增加开销 |
| 保存日志 | 需要写目录留存时开启，并检查路径可写 |
| 探针筛选 | 查看底层跟踪；未开详细跟踪时可能没有条目 |

内存日志只保留最近 2000 条，磁盘日志也有大小边界，不是永久审计存档。复现后尽快保存需要的片段。

## 别把这些现象误判成新问题

- FFmpeg 往 stderr 写诊断信息很常见，红色本身不等于失败，要同时看退出码和任务状态。
- 导入解析与处理是两个阶段：前者先查文件可读性、FFprobe；后者再查命令、参数、编码器。
- 详细日志不会修复权限、网络或编码器；它帮助看清发生了什么。
