# 3.3 处理队列：从入队到找到结果

队列保存要执行的任务，以及任务结束后的记录。先把流程“加入队列”，再开始执行，方便你在真正占用 CPU/GPU 前确认数量和输出位置。

## 跑一个或一批任务

1. 在项目页给文件或容器配置好流程并保存。
2. 用文件卡片“加入队列”、容器“全部加入队列”，或快捷向导“保存并入队”。
3. 打开“处理队列”，核对任务名称、输入和输出。
4. 点顶部“开始处理”启动等待任务；单个等待任务也有开始按钮。
5. 点任务卡片查看当前步骤、错误、流程信息、命令及日志。移动端使用详情面板呈现相关信息。
6. 完成后点“打开文件”播放结果，或“打开所在位置”定位输出。

| 状态 | 怎样理解 |
| --- | --- |
| 等待 | 已入队，还没开始 |
| 处理中 | 正在某个步骤；不是每一步都有连续百分比 |
| 已暂停 | 同一次运行的进程被冻结，仍占并发槽位 |
| 已完成 | 本任务执行结束，可打开输出检查 |
| 失败 | 展开错误与命令/日志定位原因 |
| 已取消 | 本次运行已停止，不会自动变成成功 |

## 暂停、继续与停止

“暂停”尝试冻结任务所属真实进程，“继续”解冻同一进程。两步之间切换、没有可冻结进程时，会提示无法暂停，不会只改一个状态文字。顶部“继续全部”可恢复所有暂停任务。

“停止”取消当前任务；“停止所有”停止队列调度并取消相关任务。想继续工作时，先确认哪些记录仍在等待，哪些已经取消，再按需要从项目重新入队。

> **暂停不是跨重启的断点续传。** 应用可以恢复历史任务记录，但上次暂停的任务会重置等待，不能承诺从编码到一半的位置继续。Windows 本地进程路径不支持这里使用的冻结信号，是否能暂停要以当前任务实际返回为准。

## 清理记录

- “清除已完成”会清理**已完成、失败、已取消**这些终态记录。
- “清空”在没有运行任务时清空队列。
- 终态任务可按界面入口移除；移动端还可以长按终态卡片确认移除。
- 清理记录**不会删除已经输出的成品文件**。没有其他引用的应用临时导入副本可能随之回收。

## 批量处理慢，先改哪一项

到[处理设置](../settings/processing.md)调整“同时启用任务数”。这与导入阶段的“解析线程数”不同。更多并发会增加内存、磁盘和编码器负载，不一定更快；先用少量任务比较更稳妥。

任务通知、流体云和超级岛还有系统能力及权限限制，见[平台差异](../settings/platforms.md)。
