# 3.3 处理队列与任务生命周期

队列用于管理待执行任务及任务完成后的记录。加入队列不会立即启动任务；执行前可在队列中核对任务数量和输出位置。

## 执行一个或多个任务

1. 在项目页为文件或容器配置并保存流程。
2. 在文件卡片中选择“加入队列”、在容器中选择“全部加入队列”，或在快捷向导中选择“保存并入队”。
3. 打开“处理队列”，核对任务名称、输入和输出。
4. 选择顶部“开始处理”启动等待任务；也可使用单个等待任务的开始按钮。
5. 选择任务卡片查看当前步骤、错误、流程信息、命令和日志。移动端通过详情面板显示这些信息。
6. 任务完成后，选择“打开文件”播放输出，或选择“打开所在位置”定位输出文件。

| 状态 | 说明 |
| --- | --- |
| 等待 | 已入队，还没开始 |
| 处理中 | 正在某个步骤；不是每一步都有连续百分比 |
| 已暂停 | 同一次运行的进程被冻结，仍占并发槽位 |
| 已完成 | 本任务执行结束，可打开输出检查 |
| 失败 | 展开错误与命令/日志定位原因 |
| 已取消 | 本次运行已停止，不会自动变成成功 |

## 暂停、继续与停止

“暂停”尝试冻结任务对应的实际进程，“继续”解冻同一进程。在处理步骤切换期间或不存在可冻结进程时，系统会提示无法暂停，任务状态不会仅因操作请求而改变。顶部“继续全部”可恢复所有暂停任务。

“停止”取消当前任务；“停止所有”停止队列调度并取消相关任务。重新处理时，请检查队列中仍处于等待状态和已取消的记录，并根据需要从项目重新入队。

> **暂停状态不会在重启后恢复为可继续执行的进度。** 应用可以恢复历史任务记录，但重启后，上次处于暂停状态的任务会重置为等待，不能从中断的编码位置继续。Windows 本地进程路径不支持此处使用的冻结信号；是否能够暂停，以当前任务返回结果为准。

## 清理记录

- “清除已完成”会清理**已完成、失败、已取消**这些终态记录。
- “清空”在没有运行任务时清空队列。
- 终态任务可按界面入口移除；移动端还可以长按终态卡片确认移除。
- 清理记录**不会删除已经输出的成品文件**。没有其他引用的应用临时导入副本可能随之回收。

## 调整批量处理并发数

如需调整批量处理并发数，请在[处理设置](../settings/processing.md)中修改“同时启用任务数”。该选项不同于导入阶段的“解析线程数”。提高并发数会增加内存、磁盘和编码器负载，不一定能缩短处理时间；可通过少量任务的对照运行评估效果。

任务通知、流体云和超级岛还有系统能力及权限限制，见[平台差异](../settings/platforms.md)。
