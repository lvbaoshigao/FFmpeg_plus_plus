# 3.4 命令模式

已经有一条 FFmpeg 命令，或想试一个界面没有直接提供的参数，可以用命令模式。先记住：**桌面端把命令加入队列，移动端直接运行并显示结果。**

## 从哪里打开

- 桌面端：主导航“命令”。
- 移动端：设置 → 工具 → 命令。

## 桌面：先输入，再到队列执行

把下面的占位路径换成你机器上实际存在的文件路径：

~~~text
ffmpeg -i "/实际目录/输入视频.mp4" -c:v libx264 -crf 23 -c:a aac "/实际目录/输出视频.mp4"
~~~

1. 确认输入和输出不是同一个文件。
2. 路径带空格时，用成对的单引号或双引号包住。
3. 提交命令。界面会检查能否找到 <code>-i</code> 输入、末尾输出和本地输入文件。
4. 看到“已加入处理队列”后，到队列点开始。此时的提示不是转码完成。
5. 失败时，到任务详情复制实际命令与日志。

Tab 提供一组常见参数和编码器名称的固定补全。候选里有某编码器，不能证明你的 FFmpeg 已编译进它，也不会替你检查整条命令语义。

## 移动端：只运行 FFmpeg / FFprobe

移动端只接受可执行文件名为 <code>ffmpeg</code>、<code>ffprobe</code>（也识别对应 .exe 名）的命令，不允许任意系统命令。运行使用直接进程调用，结束后集中显示输出和退出码。

这不是完整 shell：不要把管道、重定向、环境变量展开或连续多条命令当成支持语法。解析主要处理空白和成对引号，也不要套用复杂 shell 转义规则。

> **内置 FFmpeg 不等于命令页会自动修好可执行路径。** 移动端此入口按填写的可执行文件调用，不走桌面队列路径处理。提示找不到可执行文件时，先验证普通项目任务能否运行，必要时使用设备上实际可执行路径；不能据此断定设备不能转码。

## 当前边界

| 情况 | 当前行为/建议 |
| --- | --- |
| 只查版本或探测信息 | 移动端可直接尝试；桌面入队仍要求输入与输出，不能当终端 |
| 网络 URL 输入 | 桌面检查本地文件存在性，不应当作网络下载入口 |
| 多输入/多输出、复杂映射 | 桌面只用简化规则识别任务元数据；先确认识别结果，复杂命令优先用可校验的节点流程或外部终端 |
| 红色输出行 | stderr 也可能包含正常诊断；结合退出码及完整日志判断 |
| 很长的输出 | 只保留有界条目，不适合永久日志存档 |
