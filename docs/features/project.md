# 3.1 项目与媒体导入

项目页是你开始处理文件的地方。先把媒体加进来，再决定给单个文件配置流程，还是把一组文件放进容器批量处理。还没跑通过一次任务，可以先看[第一个任务](/guide/first-task)。

## 先添加一个文件

1. 打开“项目”，点“添加文件”。
2. 在系统选择器里选择视频、音频或图片。桌面也可以把受支持扩展名的文件拖进项目页。
3. 等待解析提示结束。解析用 FFprobe 读取时长、编码、分辨率、轨道等信息，还没有开始转码。
4. 在文件卡片点编辑，根据当前[编辑模式](../settings/editor.md)进入节点编辑器或快捷配置。
5. 配好并保存后，点文件卡片的“加入队列”，到[处理队列](queue.md)开始执行。

> **看到“正在解析”先别急着重加。** 大文件或复杂封装可能需要更久。解析失败先看[日志](logs.md)；“已经显示在项目中”不等于“解析成功、可以处理”。

选择器会筛选常见媒体扩展名，桌面拖放也按扩展名过滤。扩展名只是入口筛选，内容能不能读取、编码器能不能处理，还要看 FFmpeg/FFprobe 的结果。没有扩展名的文件不会因为“看起来像视频”就被桌面拖放自动识别。

## 搜索、选择与移除

文件多了，可以点搜索按钮按名称缩小列表。需要批量操作时进入多选，选择目标，使用全选、反选或删除。桌面默认项目搜索快捷键为 <kbd>Ctrl+F</kbd>，完整列表见[快捷键](../reference/shortcuts.md)。

移除主要管理应用里的项目和记录，不是一个用来清理原始媒体的文件管理器。应用自己的临时导入副本在不再被项目或队列引用时可以回收；重要原文件仍应由你自己保管。

## 一组文件用容器管理

要给十段视频套同一个流程，或把一组图片合成视频，可以从项目页的“容器”菜单开始。

| 创建方式 | 适合什么情况 | 注意点 |
| --- | --- | --- |
| 创建空容器 | 先分组，之后慢慢加文件 | 名称不能为空 |
| 从文件夹创建 | 一批媒体已经放在同一目录 | 只扫描所选目录这一层，不递归导入子目录；只收受支持扩展名的普通文件 |
| 从文件创建 | 媒体分散在不同位置 | 用选择器选取一批文件 |

进入容器后，可以重命名、添加文件、按菜单排序，也可以在单项“更多”里上移、下移、移除。容器的编辑按钮打开的是**容器共用流程**。

- 普通批量处理：保存容器流程后，“全部加入队列”会给已解析文件逐个生成任务。
- 合并媒体、图片合成视频：进入合并任务路径，文件顺序会影响结果。先核对顺序，再入队；细节见[容器与批处理](/nodes/containers)。
- 给容器中的文件“应用到文件（不覆盖容器流程）”，只改该文件的独立流程。**之后从容器运行，仍使用容器流程。**

> **移动端的导入入口并非完全一样。** 普通“添加文件”会把没有本地路径的来源流式复制到临时目录；容器的部分选文件入口当前只收带本地路径的结果。若云端/SAF 来源在容器中没加进来，先尝试可访问的本地副本。输出目录也需要 FFmpeg 能读取的真实文件系统路径。

只想顺序做几步处理，去[快捷配置](quick-config.md)；要画分支、使用逻辑门或容器合并，去[节点编辑器](/nodes/)。已有模板则看[配置库与 FPPX](library.md)。
