# 2.11 预览、探测与错误检查

这里有几种都叫“预览”的功能，但它们回答的问题不同。先确认你正在看哪一种，就不会把源素材画面误当成整条流程的成片。

## 各种预览分别能看什么

| 入口 | 实际内容 | 不能据此判断什么 |
| --- | --- | --- |
| 桌面单击工具箱元素 | 临时节点的参数表单 | 节点是否已添加、参数是否会带进新节点 |
| 片段截取、帧提取 | 指定源时间位置的画面 | 前面所有处理后的完整效果 |
| 视频/图片裁剪工具 | 参考画面、裁剪区域与坐标 | 最终编码画质或整条管线输出 |
| 提取音频的播放按钮 | 临时提取选中音频片段进行试听 | 后续降噪、音量、均衡等全部处理的效果 |
| 字幕样式示例 | 界面中的字体/颜色示例文字 | 真实视频上的最终排版和完整字幕时序 |
| 输出节点“输出预览” | 预计文件名和目录文字 | 已经输出文件或真实成片画面 |

> 当前编辑器没有统一的整条流水线实时渲染预览。要确认最终效果，保存后用短素材跑一次任务，再打开实际产物检查。

## 预览空白时按这个顺序查

1. 确认当前编辑器有真实源文件；配置库空模板没有媒体可取帧。
2. 检查源文件路径还存在，FFmpeg可用。
3. 换到有效时间或帧号，点提取/刷新。
4. 图片裁剪依赖能找到的源图片；上游运行时生成的图片可能没有即时预览，可先用已知尺寸手动填写。
5. 不要通过反复增加节点尝试“修复预览”。先用一个最小链验证源和工具可用。

音频试听若原音频编码与临时M4A不兼容，可能提取失败；这不自动代表整条正式输出链都无效。正式输出仍要选相容的编码与格式。

## 探测模式怎么用

1. 开启工具栏“探测模式”。也可在快捷键设置中给它绑定按键，默认未绑定。
2. 桌面将鼠标移到端口上；触屏按下并移动到端口附近。
3. 看提示中的数据媒体类型或门的输入、输出值。
4. 太乱时临时隐藏逻辑线；这只改变显示，不是断开或禁用逻辑。

| 提示 | 当前含义 |
| --- | --- |
| 数据输入/输出：video、audio、image | 设计图里的媒体类型 |
| 状态输出：1（成功） | 固定设计值，不是实时任务已成功 |
| 使能输入：1（悬空默认） | 端口默认启用提示，不是完整使能网络的运行结果 |
| 逻辑门：0/1 | 基于当前画布输入的门值推算 |
| ? | 悬空/环路/未知，或时间、随机、文本门在设计探测中不计算 |

不要用探测的“成功1”代替任务日志。尤其是时间、概率和文本条件，最终判定要看正式任务构建与执行。

## 保存校验能检查什么

保存时会检查节点结构和一部分参数，列出错误后暂不保存。

| 提示方向 | 怎么处理 |
| --- | --- |
| 缺少源、输出、输入线或输出线 | 接好完整链，删除未使用的孤立处理节点 |
| 多条数据输入 | 改成串行；多文件合并用容器的合并节点 |
| 类型不兼容 | 检查媒体类型；视频要先提取音频再接音频节点 |
| 存在循环连线 | 拆环；重复操作改用逻辑块 |
| 通用节点未选媒体类型 | 选中它，在属性顶部选类型 |
| 视频裁剪没有区域 | 提取帧、打开选择工具并保存选区 |
| 截取时间超出上游范围 | 按上游片段的时长重新填时间 |
| 逻辑块重复引用/包含源或输出 | 分开组织，只框处理节点 |

通过校验也不代表所有外部路径、编码器、硬件及媒体内容都可成功处理。水印路径为空时还可能主动跳过，而不是报错；有这类要求请自行检查。

## 调试信息和日志怎么配合

设置中的调试模式会记录更多节点添加、草稿保存、AI工具调用等信息。遇到问题时记下源类型、最小节点链、错误原文和发生步骤，再结合日志排查。调试模式不会替你试跑整张图，也不会让设计时端口值变成实时执行监视器。
