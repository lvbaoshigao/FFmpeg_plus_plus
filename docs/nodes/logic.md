# 2.10 逻辑门与逻辑块

逻辑门用0/1控制步骤是否执行；逻辑块把一组处理节点组织起来，决定重复、选择或按条件执行。它们不是同一种东西，先把普通数据链跑通，再加逻辑会更好理解。

## 先做一个能看懂的门控例子

1. 搭好：**开始 → 片段截取 → 帧率转换 → 输出**。
2. 从“控制与逻辑”添加“恒1”。
3. 把恒1输出用控制线接到“片段截取”的使能输入。数据线仍照原样保留。
4. 保存并试运行：恒1表示启用。
5. 想理解禁用，可把控制源换为恒0：中间步骤会跳过，但不要禁用最后的处理步骤。

> 逻辑线不传媒体，接好它不能代替数据输入。不要把恒0接在唯一的最后处理步骤上当作“暂停”：当前实现会认为没有最终产物而构建失败。

## 当前13种逻辑门

| 门 | 输入数 | 输出含义 |
| --- | --- | --- |
| 与AND | 2 | 所有输入都为1才输出1 |
| 或OR | 2 | 任一输入为1就输出1 |
| 非NOT | 1 | 输入取反 |
| 与非NAND | 2 | 与的取反 |
| 或非NOR | 2 | 或的取反 |
| 异或XOR | 2 | 两输入不同为1 |
| 同或XNOR | 2 | 两输入相同为1 |
| 恒1 | 0 | 一直输出1 |
| 恒0 | 0 | 一直输出0 |
| 时间触发器 | 0 | 系统日期/时间符合设置时为1 |
| 随机门 | 0 | 按概率和节点ID的哈希判定 |
| 文件名匹配 | 0 | 对表单中的待测文本做包含比较 |
| 文本后缀匹配 | 0 | 对表单中的待测文本做结尾比较 |

按输入数接齐端口。悬空、未知值通常按启用处理，并不会可靠地阻断任务。多个逻辑门接到同一个使能端时按“或”组合；需要“全部满足”，先经过AND再接使能端。

### 时间触发器

在属性里选日期、开始时间、结束时间；日期为空表示每天，结束为空表示匹配开始时刻所在的分钟，区间也支持22:00–06:00这种跨天范围。

界面初始显示09:00，但新门未必已经保存开始时间。请明确选择并确认时间，不要只看默认显示就认为配置完成。时间门按构建执行计划时的系统时间求值，**不是定时器，也不会在队列里等到目标时间才启动**。

### 随机门

默认概率50%，可调0–100%。当前结果由节点ID哈希与概率比较得出，同一ID和概率通常得到同一个结果；复制、重新载入导致ID变化时可能变化。它不是每帧重新抽签，也不是选择性循环的“随机挑操作”。

### 文件名与后缀门

当前界面让你填“待测文本”和“匹配文本”，执行器比较的是这两段配置文字，忽略大小写。它**不会自动把正在处理的文件名填进去**。例如待测文本movie.mp4、后缀.mp4会命中。

真正想按每个输入文件的扩展名或文件名筛选，请用下面的“条件”逻辑块。

## 建一个逻辑块

1. 在工具箱“控制与逻辑”选循环、选择性循环、分组或条件。
2. 桌面可双击逻辑块工具项进入框选，手机点按后进入框选。
3. 在画布上框住要包含的处理节点。循环类会继续询问次数；分组、条件直接创建。
4. 点框的编辑入口，在属性里继续设置。

同一个节点不能属于多个逻辑块，不支持用重叠框套出嵌套循环。源、输出和以源类型实现的逻辑门不能纳入这种处理块。

| 逻辑块 | 做什么 | 新建后的起点 |
| --- | --- | --- |
| 循环 | 重复执行框内步骤 | 次数对话框初值10 |
| 选择性循环 | 重复，并决定哪些框内步骤参与 | 新建默认全部执行 |
| 分组 | 仅组织和整体移动，不增加执行次数 | 执行一次 |
| 条件 | 按源输入文件属性决定执行/跳过 | 扩展名等于mp4，不满足跳过 |

框可整体拖动、折叠/展开。关闭框上的×会删除逻辑块，**不会把框内处理节点一并删除**；节点仍按普通连线存在。框上的端口是视觉提示，不能当普通数据端口连线。

## 循环次数、累积与失败策略

- 固定次数：1–10000；默认10。
- 区间：起始、结束、步长。例如3到10、步长2，对应3、5、7、9，共4轮，而不是执行10轮。
- 链式累积：默认关闭；关闭时每轮从原始输入开始，开启时下一轮接上一轮输出。
- 某轮失败：默认中止整个任务，可改跳过继续；重试初值0，范围0–10。

迭代变量包括{i}（当前序号）、{i0}（从0起的轮次）、{n}（总轮数）、{i:03}（补零序号）。例如参数文字中frame_{i:03}.jpg对应frame_001.jpg等。使用序号模板时要自己保证文件名唯一，程序不再替该类名字追加_loop_N后缀。

这不是只在画布上回放动画，每轮都可能执行实际处理。先用2轮、短素材试验，再增加次数。

## 选择性循环的边界

模式有全部执行、手动选择、随机选择。手动模式下勾选要参与的节点。

> **“随机选择”当前尚未实现，等同全部执行。** 新建默认采用全部。手动模式一个都没勾时，执行器不会把它当成“全部禁用”；想精准选择请至少勾一个，并检查最终步骤。

手动选择未勾选最后处理步骤时，最后步骤仍执行并产生警告。这是保证最终输出链存在的当前行为，不能用于“完全不产出”的控制方案。

## 条件块怎么填

例子：只给MP4源做中间的调色，其他格式跳过这一段。

1. 把调色节点框进“条件”块，后面另接一个始终执行的处理节点及输出。
2. 字段选扩展名、比较选等于、目标值填mp4（不用点）。
3. “不满足时”保留“跳过框内操作”。
4. 用MP4和另一格式各试一次，查看任务日志。

可判断扩展名、文件名、文件大小、完整路径、所在目录。文件大小单位为字节；10485760表示10 MiB。字符串比较忽略大小写；大于、小于等数值比较只适合文件大小。

实际判断对象是任务的**源输入文件**，不是某个中间临时产物；不能用它检测上一步输出的尺寸、时长或文件名。条件块包含最后处理步骤时，该步始终执行并警告；“不满足时中止”也不会对这个末步生效。

## 当前限制集中提醒

- 普通状态输出直接接普通使能端，画布能接但保存校验会拒绝，参见[连线限制](connections.md)。
- 执行器可能把若干兼容节点合并为一次处理。若一次处理里的节点分散在不同逻辑块，只套用其中一块参数并警告；把它们放进同一个块或拆清步骤。
- 探测显示的是设计时信号，不是实际FFmpeg任务实时状态；看见1不表示处理已经成功。
