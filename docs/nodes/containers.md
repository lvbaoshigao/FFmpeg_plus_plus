# 2.9 在容器中处理多个文件

这里的“容器”是项目里组织多个文件的对象，不是MP4/MKV那种媒体封装。打开容器的节点编辑器，才能在工具箱看到“合并媒体”和“图片合成视频”。

## 先确认处理对象

1. 在项目中把需要一起处理的文件放进同一个容器。
2. 检查文件编号和顺序，尤其是图片序列。
3. 从容器打开节点编辑器，再创建流程。
4. 运行前再次确认你修改的是容器配置，而不是容器内某个文件的独立配置。

> 文件独立配置和容器运行配置不是同一份。给容器里的某个文件应用配置库方案，不会自动改成整个容器运行用的方案。

## 合并媒体

基本链：**开始 → 合并媒体 → 输出**。

1. 在“容器”类别添加“合并媒体”。
2. 选合并模式：默认“流复制”，也可选“重新编码”。
3. 默认“按编号”排序；要改顺序，选“手动”，填完整编号列表，例如1,3,2,4。
4. 看编号验证提示，再到输出节点设置名字和目录。

| 模式 | 适合什么 | 别忽略什么 |
| --- | --- | --- |
| 流复制 | 编码、媒体参数相容的片段，快速拼接 | 不会替你自动统一不相容的素材 |
| 重新编码 | 需要统一处理的媒体片段 | 处理更慢，也不意味着任意音视频混合都可自动合成 |

手动列表用英文逗号分隔，编号从1开始；不能重复、越界或漏掉文件。比如容器有4个文件，填1,3,2只指定了3个，会提示不完整。

合并媒体接收视频/音频类型，不是叠加画面，也不是多轨混音。多文件来源由容器提供，**不要从多个源节点画多条数据线汇入合并节点**，那会触发单输入限制。

## 图片合成视频

基本链：**开始 → 图片合成视频 → 输出**。

| 参数 | 初始值与选项 |
| --- | --- |
| 帧率 | 30 fps，范围1–60 |
| 图片顺序 | 按编号；可改手动完整编号列表 |
| 输出格式 | MP4；也可MKV/AVI/WebM |
| 编码器 | H.264；也可H.265/VP9 |

操作：先核对图片编号，再选帧率和编码/格式。WebM等格式请用相容编码，不要只改后缀。需要继续处理视频时，在后面串视频节点。

**每张图片显示1/帧率秒**。例如30张图用30 fps合成，约为1秒视频；这适合图像序列，不是“30张图各显示30秒”的幻灯片工具。希望每张图长时间停留时，不要把帧率当成单张持续时间输入。

## 给普通节点指定容器文件

源接到某个处理节点时，若容器里匹配的媒体类型至少有2个，属性区可能出现“文件选择”。默认“全部处理”，可切“指定文件”，填1,3,5这样的编号。

1. 先确认该节点要求的视频、图片或音频类型在容器中存在。
2. 需要局部处理时再填指定编号。
3. 对照容器当前编号检查；增删或重排文件后重新核对。

没有对应媒体类型会被连接检查拦下。“指定文件”是节点筛选，不改变后续合并节点的完整顺序规则。

## 一个稳妥的合并练习

先用两段编码相同的短视频建容器，只放“合并媒体”，保留按编号和流复制，生成一份试片。确认顺序、声音、时长后，再加帧率转换或其他处理。这样一旦失败，就能分清是素材兼容还是后加节点的问题。
