# 2.9 在容器中处理多个文件

本章中的“容器”指项目中用于组织多个文件的对象，区别于MP4/MKV等媒体封装格式。仅在容器的节点编辑器中，工具箱才显示“合并媒体”和“图片合成视频”。

## 处理对象与前提条件

1. 在项目中将需要共同处理的文件放入同一容器。
2. 检查文件编号和顺序，尤其是图片序列。
3. 从容器打开节点编辑器，再创建流程。
4. 运行前确认编辑对象为容器配置，而非容器内单个文件的独立配置。

> 文件独立配置与容器运行配置分别保存。向容器内某个文件应用配置库方案，不会自动更新容器运行配置。

## 合并媒体

基本链：**开始 → 合并媒体 → 输出**。

1. 在“容器”类别添加“合并媒体”。
2. 选择合并模式：默认为“流复制”，也可选择“重新编码”。
3. 默认“按编号”排序；需要调整顺序时，选择“手动”并填写完整编号列表，例如1,3,2,4。
4. 核对编号验证提示，再在输出节点设置名称和目录。

| 模式 | 适用条件 | 限制 |
| --- | --- | --- |
| 流复制 | 编码和媒体参数兼容的片段；通过复制流拼接 | 不自动统一不兼容的素材参数 |
| 重新编码 | 需要统一处理的媒体片段 | 相对流复制需要更长处理时间；不保证支持任意音视频混合合成 |

手动列表须使用英文逗号分隔，编号从1开始，不允许重复、越界或遗漏文件。例如容器包含4个文件时，填写1,3,2仅指定了3个文件，会触发列表不完整提示。

合并媒体接收视频/音频类型，不执行画面叠加或多轨混音。多个输入文件由容器提供，**不得从多个源节点以多条数据线接入合并节点**，否则会触发单输入限制。

## 图片合成视频

基本链：**开始 → 图片合成视频 → 输出**。

| 参数 | 初始值与选项 |
| --- | --- |
| 帧率 | 30 fps，范围1–60 |
| 图片顺序 | 按编号；可改手动完整编号列表 |
| 输出格式 | MP4；也可MKV/AVI/WebM |
| 编码器 | H.264；也可H.265/VP9 |

操作：先核对图片编号，再选择帧率、编码器和输出格式。WebM等格式须使用兼容编码，仅修改后缀不能完成格式转换。继续处理合成后的视频时，在下游串联视频节点。

**每张图片显示1/帧率秒**。例如30张图片以30 fps合成，视频时长约为1秒，不表示“30张图各显示30秒”。本节点用于图像序列，不支持为每张图片单独指定停留时长；帧率表示每秒图片数量，不能按单张图片的持续秒数填写。

## 普通节点的容器文件筛选

源节点连接到处理节点时，若容器内匹配媒体类型的文件至少有2个，属性区可能显示“文件选择”。默认为“全部处理”；可切换到“指定文件”，填写编号，例如1,3,5。

1. 先确认该节点要求的视频、图片或音频类型在容器中存在。
2. 仅处理部分文件时，填写指定文件编号。
3. 对照容器当前编号检查；增删或重排文件后重新核对。

容器中没有对应媒体类型时，连接检查会拒绝连线。“指定文件”仅用于当前节点的文件筛选，不改变后续合并节点要求完整顺序列表的规则。

## 基础合并验证流程

使用两段编码相同的短视频创建容器，仅添加“合并媒体”作为处理节点，保留按编号排序和流复制模式，生成测试视频。核对顺序、声音和时长后，再添加帧率转换或其他处理。分阶段验证可用于区分素材兼容性问题与新增节点引起的问题。
